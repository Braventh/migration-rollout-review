# Architecture

Node 24, native HTTP and SQLite, a static browser UI, and the PostgreSQL WASM parser. The server listens only on loopback. PostgreSQL SQL is parsed, never executed; the metadata query runs only in a user's own client. See README for file configuration.

- Server owns validation, syntax parsing, bounded catalog-query generation, risk routing, snapshot normalization and Markdown.
- JSON API: POST /api/inspect (SQL → affected relations, generated query and warnings); POST /api/draft (SQL + optional snapshot + human context → proposed plan); GET/POST /api/reviews, GET /api/reviews/:id, and GET /api/reviews/:id/markdown. Use GET /api/reviews?page= with an empty value for the first page, then pass the returned next cursor. The worksheet measures the exact serialized save body against the 384 KiB limit advertised by the API.
- SQLite schema: reviews(id UUID primary key, title, updated_at, payload JSON text). Payload contains input, normalized evidence and draft decisions. Updates require the opened revision's updatedAt and compare it atomically; missing or stale versions return 409. The worksheet also supplies its revision on export. SQLite contention waits briefly and returns a retryable 503 if the lock persists.
- Static assets only; no arbitrary paths. Loopback Host/exact Origin enforcement, no cross-origin JSON endpoints, body size limit, no raw HTML rendering, CSP, and Markdown inert text rendering where user content is quoted. Do not share raw SQL or sensitive scope without review. No application query logs.
- Local mode has no app-layer authentication. The private Devin App is gated by Devin sign-in and organization sharing at the proxy; no trustworthy forwarded user identity is documented or verified, so the app does not enforce per-user ownership. Everyone in the organization who can open that app can read and update its one review library. Set REVIEW_WORKSPACE=org for hosted disclosure; this changes copy, not access control. Never expose the server directly.
- The proxy must connect with a loopback Host. Run the existing hosted app with `REVIEW_WORKSPACE=org REVIEW_ALLOWED_ORIGINS=https://rollout-desk--bbcnjtf0.preview.devinapps.com`. The allowlist accepts comma-separated exact Origin values in addition to the loopback origin. Cross-site page and asset GETs can load without an Origin header; cross-site API requests and non-GETs remain blocked even for allowlisted origins.
- Unit tests cover parser/rules, context and Markdown. HTTP integration tests use SQLite, including file-backed reopen and locking; Playwright exercises a saved browser workflow.
